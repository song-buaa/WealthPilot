## 1. 背景与问题

投研观点当前承载两类性质完全不同的内容：

- **长期价值判断**：手动导入（研报 / markdown / pdf / 粘贴）解析入库。
- **短期资讯信号**：自动拉取（Alpha Vantage / AKShare）批量生成。

二者被塞进同一套「观点库 + 待审核队列」管理，导致管理模型崩溃：

- 资料导入下「v2 待审核观点卡」积压 89 条；观点库 155 条几乎全是「公开新闻 / 待确认」，无人逐条 review。
- 短期信号时效短、量大（每对一个标的跑一次分析就来一批），且**会变质**——决策检索当前仍在喂「数据截至 2026-04-27」的过期内容，存储不仅没价值，反而误导决策。

**核心原则：持久化跟随时效性。** 长期判断值得沉淀、进库、人工 sign-off；短期信号正确的消费方式是「用时现取、用完即弃」，不进库、不审核、不在前端展示。

## 2. 目标

1. 投研观点模块**只服务长期价值判断**。
2. 短期信号**后端能力保留**，但不落持久存储、不进观点库、前端不展示。
3. 模块收敛为两个 tab：**资料导入 + 观点库**。
4. 知识层（File-as-Source-of-Truth + Chroma 索引）保持纯净，**只装长期 research view**。
5. 全程数据安全：软删除归档、可回滚、操作前备份。

## 3. 非目标 / 本期不做

- 不删除、不改动 Alpha Vantage / AKShare 连接器与拉取逻辑本身（能力完整保留）。
- 不重构投资决策模块的引擎消费逻辑——仅移除「决策检索」这个**可浏览 UI**，引擎该消费什么仍由决策侧决定。
- 不做物理删除（仅软删除归档；物理删除留作后续单独评估）。
- A 股短期信号同样适用本规则，无例外。

- 归档谓词必须**精确**，参照 `is_qmt_managed` 的精确谓词思路，绝不误伤手动导入的长期观点。
