# WealthPilot 三引擎纪律架构

本文档说明 `app/discipline/` 三引擎体系的设计理念和编排机制。

## 设计动机

传统的纪律校验通常是单一函数（"check_all_rules"），但金融投资纪律实际上有 3 类不同性质的约束：

1. **硬性约束**：违反则物理拦截（如仓位上限）
2. **策略判断**：基于市场状态的建议（如止损时机）
3. **行为约束**：心理层面的冷却（如情绪驱动的交易）

把它们混在一起会导致：
- 难以分别配置阈值
- 难以表达"BLOCK vs 建议 vs 冻结"的不同动作
- 难以单独测试和迭代

## 三引擎拆分

### Layer 1: Risk Engine（硬性约束）
- 触发动作：BLOCK（拦截操作，禁止执行）
- 包含纪律：1, 2, 3, 4, 6, 8（仓位 / 杠杆 / 流动性 / 节奏 / 熔断）
- 设计原则：违反即拦截，无策略空间

### Layer 2: Decision Engine（策略判断）
- 触发动作：建议（提示用户但不强制）
- 包含纪律：7, 9, 10（止损逻辑 / 底仓 / 动态仓位）
- 设计原则：依赖市场判断和投资逻辑，不能机械执行

### Layer 3: Psychology Engine（行为约束）
- 触发动作：冷却（24 小时禁止操作）
- 包含纪律：11（情绪冷却）
- 设计原则：保护用户不在情绪化状态下交易

## 编排器：engine_runner.py

`engine_runner.py` 按 Layer 1 → Layer 2 → Layer 3 顺序执行：

```
Layer 1 (Risk) 触发 BLOCK
  → 立即返回，不进入 Layer 2
Layer 1 通过
  → Layer 2 (Decision) 输出策略建议
  → Layer 3 (Psychology) 检查冷却状态
  → 返回综合结果
```

## 决策管道为什么用简化版

PositionDecision 决策管道在 `decision_engine/rule_engine.py` 实现的简化版，
只检查纪律 3（单标仓位上限）。设计动机：

1. **决策响应延迟**：完整 3 引擎要 200~500ms，决策管道追求 <100ms
2. **场景差异**：决策时只关心"这个标的能不能买"，不需要全局健康度
3. **完整体系异步用**：投资纪律页面、组合体检等场景异步调用 `engine_runner`

这种分流是工程上的真实权衡：实时决策路径轻量，深度纪律审计完整。
