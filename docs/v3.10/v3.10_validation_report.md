# v3.10 IBKR 下单接入 — 完整验证报告

## 1. 范围回顾

### 本期做了什么
IBKR（Interactive Brokers）下单接入：通过 ib_async 2.x 封装 BrokerAdapter，
接入 OrderManager 下单/撤单/查询全链路，在 Paper 账户（DUQ629797）完成端到端验证。

### 明确没做的（PRD §1 Out of Scope）
- IBKR 持仓拉取/同步（持仓仍走老虎/雪盈/国金）
- 条件单（CONDITIONAL_LIMIT，闸门 3 拒绝）
- Market 单（仅支持 LIMIT）
- 自动登录保活（TWS/Gateway 需手动启动并保持登录）
- A 股交易（闸门 2 拒绝，A 股走国金 QMT）
- 实盘交易（ENABLE_IBKR_LIVE_TRADING 默认 false）

## 2. 逐里程碑结论 + 证据

### M0: cancel 真撤单

**修复 bug**: cancel_order 之前只改本地状态，不通知券商。
修后分流逻辑（5 分支）：无 broker_order_id → 仅本地；已终态 → 拒绝；
有 broker_order_id → 调 adapter.cancel_order() → sync 确认真实状态。

**真连证据**: M3 端到端 audit_log 记录 `cancel_broker_responded: broker_accepted=true`，
随后 sync 确认 `status=cancelled`。

commits: `47ff63c` fix(action): cancel_order 真撤单, `edcd21e` test(action): M0 收尾

### M1: 四闸门 + 事件循环隔离

| 闸门 | 内容 | 验证 |
|------|------|------|
| 1. paper-only | 构造时预检 + 连接后 managedAccounts() 断言 DU 开头 | 单测 8 条 |
| 2. market 白名单 | {US, HK}，A 股 rejected | 单测 3 条 |
| 3. order_type 白名单 | 仅 LIMIT，条件单/市价单 rejected | 单测 3 条 |
| 4. outsideRth=False | 禁止盘前盘后下单 | 单测 1 条 |

事件循环隔离：ib_async 基于 asyncio，在独立后台线程 `ibkr-event-loop` 中运行，
通过 `run_coroutine_threadsafe` 发调用。对外接口是同步的（与 Tiger adapter 一致）。

**permId 收口**: 开市实测 256ms 回填，PERM_ID_WAIT_SECONDS=2 有余量。
broker_order_id 优先存 permId（跨 session 稳定），fallback orderId。

**Inactive/errorCode 判定纪律**:

- 200: 合约无效 → 直接 Cancelled（不经 Inactive）

- keyword fallback 降级为 unknown（不判 rejected 终态）

### 账户来源修复

**修复**: _resolve_and_verify_account 从 managedAccounts() 获取真实账户。

## 4. 已知局限 / 遗留

1. **港股未真连验证**: US/SMART/USD (TSLA) 经探针+端到端验证；
   HK/SEHK/HKD 仅有代码映射和闸门 2 白名单，未在 paper 真连下过 HK 单。
   上实盘前需先 paper 验 HK。

2. **keyword fallback 降级后覆盖面**: Inactive + 无实测码时只判 unknown 待人工。
   如果未来出现新的拒单 errorCode（如 203/104/106），在探针实测前只能走 unknown → poller 轮询。
   需要在首次实盘阶段密切监控 unknown 订单。

3. **Filled 未实盘验证**: paper 下的单都是远低于市价的不可成交单，
   Filled 状态映射和 avg_filled_price 回填未经真实成交验证。

4. **自动登录保活未做**: TWS/Gateway 需手动启动并保持登录。
   断连后 adapter 不自动重连（需手动重启应用）。

5. **risk_engine 无 IBKR 感知**: 投资纪律模块的 risk_engine 不区分 broker，
   下单前的纪律校验（仓位上限等）对 IBKR 订单和 Tiger 一视同仁。
   这是预期行为（纪律不因券商不同而放松），但需确认 symbol 格式兼容。

6. **_error_codes 映射不持久**: adapter 重启后 _error_codes dict 清空。
   如果 Inactive 订单的 error callback 在 adapter 重启前到达、重启后查，
   callback 信息丢失 → fallback 到 trade.log（可能 errorCode=0）→ unknown。
   低频边缘场景，当前可接受。
