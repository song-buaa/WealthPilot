# v3.6.5 Patch: wp-retrieve-principles LLM 注入修复

**类型**: Bug Fix Patch
**优先级**: 中（用户可感知的数据展示与 LLM 推理脱节）
**预计工作量**: 1 天代码 + 2-3 天评测基线校准

## 背景

v3.7 勘探发现 v3.6 引入 wp-retrieve-principles 时数据流半接通：

- data_loader.load() 第 7b 步 KnowledgeStore.retrieve() — 正常召回
- explain API 序列化 retrieved_principles — 正常传到前端
- 前端 KnowledgeCitations 组件 — 正常渲染引用卡片
- **llm_engine.reason() — 不消费 retrieved_principles 字段**

导致 position/portfolio 路由下"用户看到的知识引用卡片"和"LLM 实际推理依据"脱节。

general 路由不受影响（ExpressingAgent._express_general_chat() 已完整接通）。

## 修复范围

1. **llm_engine.reason()** 消费 `LoadedData.retrieved_principles` 字段，注入 LLM prompt
2. **ExpressingAgent._express_position_decision()** 接通 `_build_citation_block()` 调用（当前已定义但零调用）
3. **L3 评测基线重建**: 18 个回归用例全量重跑，逐 case 校准 5 维度评分

## 启动条件

v3.7 合入后立即可启动，不要求等待日志数据。v3.7 日志仅用于确认影响频率，不作为 v3.6.5 启动的前置条件。

## 风险

- prompt 变更会改变所有 LLM 输出（至少多一段引用），需要逐 case 人工审核
- 评分变化可能是真改善、可能是输出变长导致的虚假提升、可能改变决策档位
