### 场景 4: 撤已成交单
- cancel_order(已成交单) 返回 True (不是预期的 False)
- Tiger 模拟盘对已成交单的 cancel 请求不报错也不拒绝,返回订单 ID
- 实际效果: 订单状态仍为 filled,cancel 无操作但不报异常
- **注**: 实盘行为可能不同(实盘可能返回 ApiException),M6 实盘验证时已确认实盘 cancel 行为正常

### 场景 5: not_found 补测
- 已撤订单 43213710163723264 仍可查到,status=cancelled
- Tiger 保留历史订单查询能力,不会 not_found
- not_found 只会在"place_order 返回了 ID 但 Tiger 端还没同步"的极端窗口发生
- 结论: not_found 重试路径在正常场景下不会触发,但代码逻辑已验证正确(M8.2 单测覆盖)

### 场景 6: 部分成交观察
- 10 股 QQQ @ $710,3s 内全部成交(filled=10)
- 模拟盘流动性太好,无法触发 partially_filled
- 结论: 部分成交代码逻辑已由 M1.2 单测覆盖(64 个测试),真实场景需在低流动性标的/大单量时观察
