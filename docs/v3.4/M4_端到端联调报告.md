## 5. 发现的接缝问题

### 5.1 Symbol 格式: `0700:HK` vs `00700:HK` (已修正)

第一次跑 Task 3 时用了 `0700:HK`,Tiger 返回"合约不正确"。
原因: `_parse_symbol("0700:HK")` 正确返回 `("HK", "0700")`,但 Tiger 期望 5 位代码 `00700`。
修正: 测试数据改为 `00700:HK` 后成功。

**影响**: Symbol 标准化专项需要确保 LLM 输出的港股代码是 5 位零填充格式。Adapter 层不做 padding,遵循"标准化由上游负责"原则。

### 5.2 A 股 market 标识: `SH` vs `CN`

用户输入 `600519:SH` → `_parse_symbol` 返回 market=`SH`。白名单拦截消息显示"不支持市场 SH"。
这是正确行为(SH 不在白名单),但消息不够友好——没有提示"A 股应用国金 QMT"。

原因: 白名单拦截代码只检查 `market not in {"US", "HK"}`,没有特判 SH/SZ → A 股。
**建议**: M5 UI 层展示时可补充映射 SH/SZ → "A 股"。Adapter 层当前行为已安全(拦截)。

### 5.3 audit_log fx_rate_to_cny 只在 order_submitted/rejected 事件中

审计日志检查显示:
- `order_submitted` / `order_rejected`: fx_rate=Y (通过 _enrich_audit_payload)
- `order_synced` / `order_created` / `draft_*`: fx_rate=N

这符合 M3 设计: 只在 place_order 路径(有 raw_response 含 currency)时补充汇率。
sync 路径的审计也可以补,但 M3 范围不做——留给 M5 如有需要再加。
