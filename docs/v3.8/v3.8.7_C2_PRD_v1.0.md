### 2.2 user_query bug 修法（勘探 B1/B2）

bug：`run()` 收到 user_query（L60），但调 `_execute_general` 时没透传（L80-81），
`_execute_general` 从不存在的 `intent["user_query"]` 取到空串。

修法（与 position/portfolio 分支完全一致的现成模式）：
- `_execute_general` 签名加 `user_query: str` 参数
- L81 改为 `self._execute_general(out, planning_output, user_query)`
- 内部删掉 L626-631"从 intent 取 user_query"，直接用传入参数
- 影响面极小：`_execute_general` 内只有 2 处用 user_query（L635 关键词判断、L642 检索 query）

### 2.3 接通的返回契约暗礁（勘探 A3，C2 必须解决）

retrieve 接通比 C1 复杂，因为直连与 Skill 版返回契约不一致：

| | 直连 store.retrieve()（现状） | invoke_skill → execute_retrieve_principles |
|---|---|---|
| 返回类型 | list[RetrievedChunk]（对象） | dict（含 chunks: list[dict]，序列化过） |
| source_types | general 现状只查 allocation_principles | 默认全三类 |
| top_k | general 现状 3 | 默认 5 |

下游 ExpressingAgent 用 `getattr(c, "content")` 取内容——拿到 dict 会失败。
**所以 flag 开分支必须做适配**：把 invoke_skill 返回的 dict 转回 list[RetrievedChunk]（或等价
可被 getattr 读的对象），并对齐查询参数（source_types/top_k 与直连一致），否则双轨不等价。

### 2.4 只包一处、不碰 position/portfolio（勘探 C2/C3）

C2 双轨只包 `_execute_general` L637-654 的 KnowledgeStore.retrieve() 那一处。
position/portfolio 的 retrieve 在 data_loader.load() 内部被 load-context 吞掉，C2 **不碰**
（接通它要改 data_loader，影响面大，留后续）。→ Case1-4 可信基线不受影响。

## 3. C2 设计

### 3.2 第二件：retrieve 双轨接通（flag + 返回契约适配）

```python
# flag:WP_USE_SKILL_RETRIEVE_PRINCIPLES,默认关
def _use_skill_retrieve_principles() -> bool:
    return os.environ.get("WP_USE_SKILL_RETRIEVE_PRINCIPLES", "") == "1"

# _execute_general 里 retrieve 那处(原 L637-654)双轨:
if self._should_retrieve_principles(user_query):
    out.invoked_skills.append("wp-retrieve-principles")
    if _use_skill_retrieve_principles():
        # 新路径:经 invoke_skill
        from backend.skills import invoke_skill
        raw = invoke_skill(
            "wp-retrieve-principles",
            query=user_query,
            source_types=["allocation_principles"],  # 对齐直连参数,不用默认全三类
            top_k=3,                                   # 对齐直连参数,不用默认 5
        )
        # 返回契约适配:dict -> list[RetrievedChunk],保证下游 getattr(c,"content") 可用
        results = _adapt_retrieve_result(raw)
    else:
        # 老路径:直连(保留)
        store = KnowledgeStore.get_instance()
        results = store.retrieve(...) if store.is_ready() else []
```

**适配函数 `_adapt_retrieve_result`**：把 invoke_skill 返回的 `{"chunks":[dict...]}` 转回
`list[RetrievedChunk]`（用 RetrievedChunk 的 model_validate 或等价），确保和直连返回同类型同结构。
这是 C2 的技术核心，flag 开/关两条路最终塞进 LoadedData.retrieved_principles 的东西必须同类型。
